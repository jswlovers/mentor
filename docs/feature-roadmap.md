# 미용 SOS 추가 기능 설계서

현재 서비스의 빈틈을 기준으로 **다음에 만들 기능**을 우선순위와 함께 설계한 문서입니다. 1장은 이번에 구현을 마친 카카오톡 알림입니다.

---

## 1. 현재 상태와 가장 큰 빈틈

> **진행 현황:** 아래 "가장 큰 빈틈 3가지"는 P1 구현(4장 A·B·C)으로 **해결됐습니다.** 4장은 설계와 함께 구현 결과를 `[구현 완료]`로 표시했습니다. 남은 것은 D(약관 문안 확정)와 P2 이후입니다.

**구현 완료:** 로그인 · 질문/답변(사진) · 전문가 신청/승인 · 1:1 상담(채팅·보이스톡·페이스톡, 동시 종료) · 코인 원장/정산/출금/환불 · 인앱 알림 · 후기/프로필 · 고객센터/신고 자동 정지 · 관리자 화면 · 카카오톡 알림 · **P1: 전문가 호출 알림 · 무응답 자동 환불 · 전문가 목록·검색·분야 · 약관 게시/동의(초안)**

**가장 큰 빈틈 3가지**

1. **전문가가 상담 요청을 모릅니다.** 질문자가 시작비를 내고 상담을 열어도, 전문가에게 "지금 상담이 열렸다"고 알려주는 경로가 없습니다. 전문가가 우연히 질문을 열어야만 참여합니다.
2. **전문가가 오지 않으면 돈이 묶입니다.** 참여 전에는 수동 취소만 가능해 질문자가 직접 취소해야 합니다.
3. **전문가를 찾을 방법이 없습니다.** 전문가 목록·검색·분야 표시가 없어 질문자가 누구에게 물을지 고를 수 없습니다.

아래 P1 기능은 이 세 가지를 직접 해결합니다.

## 2. [구현 완료] 카카오톡 알림톡

### 동작
| 단계 | 내용 |
|---|---|
| 준비 | 내 정보 → 휴대폰 번호 입력 → 문자 인증번호(6자리, 5분, 5회 시도) → 수신 동의 체크 |
| 발송 대상 | **휴대폰 인증 + 수신 동의를 모두 마친 회원**만 |
| 발송 시점 | 새 채팅 메시지 · 전문가 참여 · 답변 등록 · 충전 승인/반려 · 전문가 승인/반려 · 출금 지급 · 문의 처리 · 관리자 안내 |
| 채널 선택 | 종류별 알림톡 템플릿 ID가 있으면 **알림톡**(실패 시 Solapi가 문자로 자동 대체) → 없으면 문자(`SMS_PROVIDER=solapi`) → 아무것도 없으면 **mock**(서버 로그만) |
| 비용 통제 | 같은 종류(새 메시지·답변)는 30분에 1회로 제한, 정지 회원 제외 |
| 기록 | 모든 발송이 `message_log`에 채널·종류·문구·상태(sent/mock/failed)로 저장, 관리자 화면 **메시지** 탭에서 조회 |
| 관리자 안내 | 회원 아이디 또는 `all`(동의 회원 전체)에게 서비스 안내 발송 (500자, 광고 금지) |

### 법·정책 기준 (구현에 반영한 것)
- 서비스 이용 알림은 **거래 관련 정보성 메시지**로, 광고성 정보와 분리했습니다. 관리자 안내는 서비스 안내 전용이며 광고 발송 기능은 두지 않았습니다.
- 수신 동의 시각을 저장(`notify_consent_at`)하고 내 정보에서 **언제든 철회**할 수 있습니다. 번호 삭제 시 동의도 함께 지워집니다.
- 번호는 **본인 인증번호를 통과한 것만** 저장·사용합니다(오입력 번호로의 발송 방지). 한 번호는 한 계정에서만 인증됩니다.
- 화면에는 번호 일부만 표시합니다(`010-****-5678`).

### 실제 발송을 켜려면 (사람이 할 일)
1. 카카오톡 **채널 개설 + 비즈니스 인증**
2. **Solapi** 가입 → 채널 연동 → **발신번호 등록** → 충전
3. 알림톡 **템플릿 12종 등록·심사**(문구는 관리자 매뉴얼 2-7장 표) → 승인된 ID를 `.env.local`에
4. 서버 재시작 → 본인 번호로 시험 발송
- 심사 기간과 건당 요금은 Solapi·카카오 기준을 확인하세요. 자유 문구(`관리자 안내`)는 심사에서 반려될 수 있어 대체안(용도별 고정 문구)을 관리자 매뉴얼에 적어 두었습니다.
- **인증번호 문자는 알림톡이 아니라 일반 문자**입니다. 실제로 회원이 인증하려면 `SMS_PROVIDER=solapi`가 필요합니다(현재 mock이라 회원은 인증번호를 받지 못함).

## 4. P1 상세 설계

### A. 전문가 호출 알림 [구현 완료]
**목표:** 상담이 열리면 적합한 전문가에게 즉시 알려 첫 응답 시간을 줄인다.

- **데이터:** `expert_categories(user_id, category)` — 전문가가 담당 분야(펌·염색·탈색·커트·클리닉·매장운영)를 고른다. `users.expert_available`(응대 가능 스위치).
- **동작:** 질문자가 상담을 시작하면 → 해당 카테고리 담당 + 응대 가능한 전문가 중 **최대 N명**(예: 5명)에게 인앱 알림 + 알림톡 `consult_request`("○○ 질문에 1:1 상담이 열렸어요. 참여하면 수익이 쌓여요"). 15분 뒤 미참여면 다음 N명에게 확대.
- **선정 기준:** 응답률·평점 높은 순 + 최근 참여 이력이 적은 순(라운드로빈).
- **API:** `POST /api/consultations`(기존)에서 호출 로직 추가, `POST /api/experts/settings`(분야·응대 여부).
- **화면:** 전문가 센터에 분야 체크박스와 "지금 상담 받기" 토글.
- **지표:** 상담 시작 → 첫 전문가 참여까지 시간(중앙값), 호출 대비 참여율.
- **위험:** 알림 남발 → 전문가 이탈. 한도(1인당 시간당 3건)와 야간 제한을 둔다.

### B. 무응답 자동 환불 [구현 완료 · 기본 60분]
**목표:** 전문가가 오지 않으면 자동으로 전액 환불해 신뢰를 지킨다.

- **정책안:** 상담 시작 후 **N분(권장 30분~2시간) 내 전문가 미참여** 시 자동 취소·전액 환불, 질문자에게 알림.
- **동작:** 서버 내 주기 작업(1분 간격) — `status='open' AND expert_id IS NULL AND started_at < now - N분` 인 상담을 기존 취소 로직(`cancel`)으로 처리. 이미 검증된 환불 경로를 재사용한다.
- **추가:** 만료 10분 전 "곧 자동 환불돼요, 계속 기다릴까요?" 알림 + 연장 버튼(선택).
- **주의:** 서버가 재시작되어도 다음 주기에 따라잡도록 **DB 시간 조건**으로만 판단(메모리 타이머 금지).

### C. 전문가 목록·검색·분야 태그 [구현 완료]
- **데이터:** A의 `expert_categories` 재사용 + `users.expert_headline`(한 줄 소개).
- **API:** `GET /api/experts?category=&sort=rating|responses|recent&q=` — 승인된 전문가만, 평점·후기 수·완료 상담 수·평균 응답시간 포함.
- **화면:** `/experts` 목록(카테고리 칩, 정렬), 카드에 배지·평점·분야. 질문 등록 시 **전문가 지정 요청**(선택): 지정하면 그 전문가에게 우선 호출.
- **주의:** 평균 응답시간 등 지표는 데이터가 쌓인 뒤 노출(표본 부족 시 숨김).

### D. 약관 · 개인정보 처리방침 · 환불 규정 [화면·동의 구현 완료 · 문안은 초안, 법률 검토 필요]
공개 서비스로 운영하려면 필수입니다. 코드보다 **문안 확정**이 선행입니다.

- **게시 페이지:** `/terms`, `/privacy`, `/refund-policy`, 가입 화면에 동의 체크(필수 항목), 동의 버전·시각 저장(`users.terms_version`, `terms_agreed_at`).
- **반드시 확인할 것(전문가 검토 필요):** 통신판매업 신고 여부, 코인(선불 충전금) 관련 규제와 환불 의무, 사업소득 원천징수(전문가 출금 시 3.3% 등)와 지급명세 처리, 개인정보 수집·보관 기간, 상담 채팅 보관·파기 정책, 미성년자 가입.
- **관련 화면 문구:** 환불 규정은 현재 "전문가 참여 전 전액 환불"만 구현되어 있어, 그 밖의 규정(참여 후 환불 기준 등)을 명문화해야 합니다.

## 5. P2 요약 설계

### E. 예약 상담 + 리마인드
- `bookings(id, room_id, expert_id, asker_id, starts_at, status)`. 전문가가 가능 시간(주간 반복 슬롯)을 등록 → 질문자가 슬롯 선택 → **시작비 결제 시점에 예약 확정**.
- 시작 1시간 전·10분 전 알림톡 리마인드. 노쇼 정책(양측): 질문자 노쇼 시 시작비 몰수 vs 일부 환불, 전문가 노쇼 시 전액 환불 + 페널티.

### F. 카카오 로그인
- 카카오 디벨로퍼스 앱 등록, OAuth 인가코드 방식. `users.kakao_id` 연결, 기존 계정에 **연동**하는 흐름과 신규 가입 흐름 모두 필요.
- 얻는 것: 간편 가입, **카카오 채널 친구추가 여부** 확인(알림톡 도달률), 비밀번호 분실 감소. 휴대폰 인증은 여전히 별도 필요(카카오에서 받은 전화번호 제공 동의 시 대체 가능).

### G. 쿠폰 · 첫 상담 할인
- `coupons(code, type, value, max_uses, expires_at)`, `coupon_redemptions`. **회계 원칙:** 쿠폰은 결제가 아니라 **판촉비**로 처리 — 원장에 `platform:promo` 차변 / 회원 코인 대변(기존 가입 보너스와 같은 구조).
- 남용 방지: 인증된 휴대폰 1번호당 1회, 유효기간, 전문가 정산 기준은 **할인 전 금액**인지 **실결제액**인지 결정 필요.

### H. 관리자 통계 대시보드
- 일/주/월: 신규 가입, 질문 수, 상담 시작·참여율·평균 응답시간, 충전액, 플랫폼 매출(원장 `platform:revenue`), 전문가별 수익, 환불률, 알림톡 발송/실패.
- 원장 기반 SQL 집계 + 간단한 차트. 개인정보 없는 집계만 표시.

### I. 전문가 자격 증빙
- 신청 시 미용사 면허증 사진 업로드(`expert_documents`), **관리자·본인만 열람**(비공개 경로, 첨부 접근 검사 재사용), 승인 후 보관기간 경과 시 자동 파기.
- 승인 화면에 증빙 이미지 표시.

### J. 질문 검색 · 정렬 · 수정/삭제
- SQLite FTS5로 제목·본문 검색, 해결/미해결·카테고리·최신/답변 많은 순 정렬.
- 질문 **사진 삭제**와 본인 질문 수정/삭제(상담이 열린 뒤에는 잠금).

## 7. 추천 진행 순서

| 단계 | 내용 | 기간(추정) | 목표 |

| **0. 운영 준비** | 카카오 채널·Solapi·템플릿 심사, 입금 계좌, 포트포워딩, 약관 문안 | 1~2주(심사 대기 포함) | 실제 발송·실충전 가능 |
